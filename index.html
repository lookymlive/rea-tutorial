Usar REA para entender cómo funciona un software y construir el tuyo

REA conecta a tu agente de IA con herramientas de ingeniería inversa. Esta guía va de la instalación a un flujo de trabajo completo, para un proyecto personal o para un SaaS.

Qué es REA

REA (Reverse Engineer Anything) es un servidor MCP y una CLI. Tu agente lo usa para inspeccionar binarios nativos, apps JavaScript y Electron, ensamblados .NET, APKs y sitios web. REA devuelve hallazgos junto con la evidencia y las limitaciones de cada conclusión. El análisis corre en tu máquina; tu agente recibe los resultados, y el proveedor del modelo tiene su propia política de datos.

Si querés analizar…Necesitás
Binarios nativosHopper, Ghidra o IDA (ya instalados)
JavaScript / ElectronNode.js y npm; en Linux, un ps compatible con procps
.NETNada extra (análisis estático)
Sitios webUn navegador basado en Chrome
APKs AndroidJADX headless y un JDK completo

Requisito base: Node.js 22.x (≥22.19), 24.x (≥24.11) o 26+, más npm. La lista completa de objetivos está en el README del repositorio.

Uso responsable

REA es para investigación lícita, educación, interoperabilidad, preservación de software y análisis de software propio o que estés autorizado a examinar. El proyecto lo deja escrito en su DISCLAIMER.

Antes de cada análisis preguntate: ¿es mío, es open source, o tengo permiso y licencia para examinarlo? Si la respuesta es no, no sigas. Las herramientas comerciales (IDA, Hopper, JEB) requieren licencia legítima.

Instalación

1

Verificá Node.js

node --version
npm --version

Tiene que ser 22.19+, 24.11+ o 26+.

2

Registrá REA en tu agente

npx rea-agents setup

Elegí tus agentes, revisá los cambios propuestos y aprobalos. El setup agrega el servidor MCP de REA y las instrucciones de trabajo, y guarda backups de tu configuración. Funciona con Claude Code, Codex, Cursor, Gemini CLI, Grok Build y otros.

3

Reiniciá el agente

Sin reiniciar, el agente no ve las herramientas nuevas.

4

Instalá la CLI (opcional, recomendado)

npm install --global rea-agents
rea --help

La CLI te deja correr los mismos análisis desde la terminal y usarlos en scripts.

5

Mantenelo actualizado

REA cambia rápido y cada versión trae correcciones.

# CLI instalada globalmente
rea update

# Si usás npx: refrescá el registro del agente
npx rea-agents@latest setup

Descargá REA solo de github.com/morluto/rea, rea.tools o el paquete rea-agents en npm. Un repo con nombre parecido no es oficial.

Primer análisis

Desde la terminal

Con una app JavaScript/Electron ya extraída (carpeta o ASAR), usá una ruta absoluta:

npx -y rea-agents@latest analyze-javascript-application /ruta/absoluta/a/la/app --json

El resultado lista módulos, imports y límites de Electron, cada uno con su evidencia.

Desde tu agente

Pedile algo concreto, con la pregunta, el objetivo y el entregable:

Usá REA para entender cómo [funcionalidad] funciona en [mi app / app autorizada].
Mostrame la evidencia de cada conclusión y marcá lo que no pudiste confirmar.
Después proponé un diseño para implementarlo en mi proyecto.

Proyecto personal

Para un proyecto propio alcanza con un ciclo corto: preguntar, verificar, construir.

1

Elegí una sola pregunta

"¿Cómo guarda el estado esta app?" rinde más que "explicame todo".

2

Pedí evidencia

Exigí rutas de archivo, módulos y referencias. Si el agente afirma algo sin evidencia, pedile que lo respalde o que lo marque como hipótesis.

3

Implementá con tests

Pedile al agente que escriba la versión propia y los tests que comparan su comportamiento con lo observado. Escribí tu código, no copies el del objetivo.

4

Anotá lo aprendido

Guardá en el repo un docs/hallazgos.md con pregunta, evidencia y decisión. Te ahorra repetir el análisis.

Flujo para un SaaS

En un producto con clientes, sumá método y trazabilidad.

1

Definí alcance y autorización

Anotá qué analizás, por qué y con qué permiso (licencia, open source, acuerdo de interoperabilidad). Esto protege a tu empresa.

2

Separá investigación de implementación

Una persona o sesión investiga y produce una especificación escrita; otra implementa desde esa especificación. El código final nace de tu spec, no del objetivo.

3

Guardá la evidencia

Usá --json en la CLI y versioná los resultados importantes. Así cualquier decisión técnica se puede auditar.

4

Verificá contra la fuente oficial

Si el objetivo es un servicio con API pública, la API documentada manda. REA te ayuda a entender, no reemplaza el contrato oficial.

5

Automatizá en CI

Corré la CLI de REA en un job para detectar cambios entre versiones de un componente que dependa de terceros autorizados.

Ejemplo: SaaS que edita y publica videos

Supuesto de este ejemplo: querés una herramienta que edite videos tuyos o de tus clientes y los publique en YouTube, Instagram y TikTok. Trabajá solo con contenido sobre el que tenés derechos. Publicar se hace con las APIs oficiales; no hace falta (ni corresponde) hacer ingeniería inversa de esas plataformas.

Arquitectura

CapaQué haceHerramienta
SubidaRecibe el video del usuarioTu backend + almacenamiento de objetos
EdiciónRecorta, cambia formato, agrega subtítulosFFmpeg en una cola de trabajos
PublicaciónSube a cada red con la cuenta del usuarioYouTube Data API, Instagram Graph API, TikTok Content Posting API
CuentasEl usuario autoriza tu appOAuth 2.0 en cada plataforma

Paso a paso

1

Editá con FFmpeg

# Recortar entre dos tiempos sin recomprimir
ffmpeg -i entrada.mp4 -ss 00:00:05 -to 00:00:35 -c copy recorte.mp4

# Pasar a vertical 9:16 (Reels, Shorts, TikTok)
ffmpeg -i recorte.mp4 \
  -vf "scale=1080:1920:force_original_aspect_ratio=increase,crop=1080:1920" \
  -c:a copy vertical.mp4
2

Registrá tu app en cada plataforma

Creá la app en Google Cloud (YouTube), Meta for Developers (Instagram) y TikTok for Developers. Cada una te da credenciales OAuth. Revisá en su documentación los permisos, el proceso de revisión de la app y las cuotas, porque cambian con el tiempo.

3

Implementá la publicación

YouTube sube con el método videos.insert. Instagram publica en dos pasos: crear un contenedor de media y después publicarlo. TikTok usa su Content Posting API. Cada plataforma impone límites de duración, tamaño y formato, así que validá el archivo antes de enviarlo.

4

Dónde entra REA

Usalo en lo que sí es tuyo o está autorizado:

  • Entender una app de escritorio de edición open source o con licencia que permita interoperar, por ejemplo cómo guarda sus proyectos, para que tu SaaS importe esos archivos.
  • Analizar tu propio prototipo o una versión anterior de tu producto cuando perdiste el código.
  • Inspeccionar el comportamiento de tu propio sitio para documentar rutas y llamadas.
Usá REA para analizar la app de edición en /ruta/a/app (open source / autorizada).
Quiero saber cómo serializa un proyecto: formato, campos y versiones.
Mostrame evidencia y escribí una especificación del formato que mi SaaS pueda importar.

Lo que esta guía no hace. No sirve para descargar o copiar videos ajenos, ni para sortear los controles, términos o APIs de YouTube, Instagram o TikTok. Reeditar y resubir videos de terceros sin permiso suele violar derechos de autor y los términos de cada plataforma, y puede costarte la cuenta.

Problemas comunes

El agente no ve las herramientas de REA

Reiniciá el agente después del setup. Si sigue igual, corré npx rea-agents@latest setup y revisá que el cambio se haya aplicado.

Falla en Linux con análisis de JavaScript, Ghidra o JADX

REA necesita un ps compatible con procps en el PATH. Instalá el paquete procps de tu distribución.

Hopper muestra un diálogo la primera vez (macOS)

Elegí modo demo o activá tu licencia en esa ventana, en la misma sesión de usuario, antes de lanzar tu primera operación.

Binarios muy grandes se cortan por tiempo

Subí el plazo con las variables REA_GHIDRA_STARTUP_TIMEOUT_MS o REA_HOPPER_STARTUP_TIMEOUT_MS.

Encontré un bug

Actualizá primero. Si persiste, abrí un issue en el repo con versión de REA, tipo de objetivo, pasos para reproducir y el error.

Checklist

  • Tengo autorización o licencia sobre lo que analizo.
  • Hice una pregunta concreta y pedí evidencia.
  • Escribí una especificación y mi propio código.
  • Guardé los resultados en --json y documenté la decisión.
  • Para publicar en redes usé las APIs oficiales y contenido con derechos.
  • Mantengo REA actualizado con rea update.
Guía no oficial. Fuente de verdad: repositorio de REA, guías y documentación oficial. Verificá siempre las versiones y requisitos vigentes.
